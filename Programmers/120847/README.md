### [ Programmers ] 최댓값 만들기(1)

### 🛠️ 풀이 접근 및 분석

  - **접근 1**
    - 최댓값을 만들기 위하여 numbers 를 순회를 돌며, 가장 큰 두개의 값만 찿고 break 를 해버리면 되지 않을까 라고 생각했지만, 최악의 경우 O(N^2) 의 시간복잡도를 가질 수 있다라는 사실 떄문에, 정렬을 하면 Tim Sort 를 사용하니 최악의 경우에도 O(NlogN) 의 시간복잡도를 가지게 되니 더 효율적이라고 판단했다. 정렬 이후, 가장 마지막 두 값을 곱한 것을 반환한다면, 단순 인덱스 조회는 O(1) 이니, O(NlogN) 의 시간복잡도를 가지며, 정렬된 numbers 를 저장할 공간에 대하여 O(N) 의 공간복잡도를 가지게 된다.

### 📝 추후 개선점
  - 다른사람들의 풀이를 보다 하나 실수한 사실을 깨달았다. sorted 를 사용하면서 배열을 복사하였기에, O(N) 의 공간복잡도가 필연적으로 발생했지만, 반대로 생각해보면, inplace 정렬을 사용한다면 굳이 추가적으로 공간을 사용할 필요가 없으니, O(NlogN) 의 시간복잡도는 그대로 두되, O(1) 의 공간복잡도를 가지게 개선할 수 있었다.

### 💻 풀이 코드

```python
# 풀이 1
def solution(numbers):
    s = sorted(numbers)
    return s[-1]*s[-2]
```
